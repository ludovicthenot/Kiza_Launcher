Kiza Launcher 0.0.316

A first launch that asks one question instead of five, settings pages that open
at their top, and the four fixes from 0.0.315 — which was built and never
published.

## New

**The first launch is one screen.** It was five steps down a sidebar: Microsoft,
Runtime, Performance, APIs, Ready. Four of them asked for nothing the launcher
could not do itself — the runtime step offered to install Java, which Kiza
already installs on its own the first time you play, and the APIs step was a
read-only list of service statuses with no action on it at all. Every word of it
was in English, in a launcher that speaks French.

There is one real decision on a first launch, so there is one screen: sign in,
or carry on without an account. The memory profile stays, because it is a
genuine choice with a real consequence, but it sits on one line and is already
answered. The sign-in code appears in place with a button to copy it, and the
screen notices on its own when the browser half is done.

## Fixed

**Settings pages opened wherever the last one was left.** The panel is one
scrolling element shared by all eleven pages, and its position survived the
switch: leaving Storage halfway down opened Minecraft and Java halfway down too
— usually at its very bottom, where the wheel does nothing. It reads as a broken
scrollbar rather than as a position nobody reset. Measured before and after:
Minecraft opened 262 pixels down and would not move; it opens at zero now.

**The way out of the first screen was invisible.** "Continue without an account"
was drawn, measured and clickable at `opacity: 0`, left there by the entrance
animation. The screenshot check now fails if either way forward stops being
visible.

**The launcher crashed on the first update check that worked.** The interface
has always declared that a mod carries the list of files it owns, and the
backend never sent it. Two places call a method on that list, and neither could
run while mods carried no provenance — nothing was ever found to update or to
blame. Recording provenance made the update check work and the first candidate
took the interface down. The field is sent, both places are defended, and a test
compares what the interface reads against what the backend sends.

**Exporting failed on "Duplicate filename".** A mod can appear twice in the
catalogue and both records name the same jar, so the export added that file
twice and a zip refuses that outright.

**The same mod could be installed twice, from two catalogues.** Kiza identifies a
project as `provider:id`, so Modrinth's Fabric API and CurseForge's Fabric API
were strangers: a pack drawing from both installed it twice, and two copies of
one mod is a game that will not start.

**An imported instance lost every mod's identity.** Right names, no icons, and
"Imported File" under each one — the archive carried each mod's release but not
what the catalogue knew about it. The description, author, icon, page and
catalogue of origin travel now.

## Changed

**Importing starts the game download** when the machine does not already have
that Minecraft version. Version files are shared between instances, so importing
a pack for a version you already play still needs nothing.
