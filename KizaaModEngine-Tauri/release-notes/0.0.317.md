Kiza Launcher 0.0.317

NeoForge joins Fabric and Forge, a shared CurseForge pack finally imports, an
export becomes a pack other launchers can open, and the in-game menu stops
drawing a stretched logo over buttons that are not there.

## New

**NeoForge.** It sits beside Vanilla, Fabric and Forge when you create an
instance, from Minecraft 1.20.2 onward — the versions before that are published
as a different artefact left over from the fork, and belong to Forge. NeoForge
kept Forge's installer, so everything after the download is the same code;
what differs is where builds come from and how they are numbered.

Two things it does not have yet, and it says so rather than pretending. The Kiza
in-game client has no NeoForge build: its entry point lives somewhere the Forge
one does not, so shipping that jar would produce a mod the loader never starts.
And Kiza cannot manage shaders on it — OptiFine does not run there, and the
Forge port of Iris is a separate project Kiza has never installed.

**A CurseForge pack shared with you now imports.** A CurseForge export is a
manifest naming each mod by number, a folder of settings, and nothing else: the
mods are for the launcher to fetch. Kiza did that for a pack opened from the
catalogue and refused the identical file on disk, telling you to find it in a
catalogue it may never have been published to. Open it from Import.

**An export is a pack, not a folder with a manifest on top.** The file list was
empty and catalogue mods were not carried either, so every launcher but Kiza
opened the archive and found the mods gone. The window now asks which kind of
archive you want, first, because it changes every size beneath it:

- **CurseForge pack** — CurseForge mods are listed rather than copied. Any
  launcher opens it, and it stays small.
- **Self-contained** — every jar is inside. No network, no key, nothing that
  can stop being published; only Kiza reads it as an instance.

A `modlist.html` travels with it, the page you open in a browser to see what is
in a pack before installing it.

## Fixed

**The Minecraft logo was stretched.** Its texture is 1024x256 pixels standing
for 256x64 units, with the wordmark in the top 44 of them; the renderer was
told the texture was 44 units tall — the size of the wordmark, not of the sheet
— so it squeezed 64 units of image into 44 and the wordmark came out 45 per cent
too wide for its height. Versions before 1.20 store it as two halves side by
side, which the renderer had never accounted for at all.

**Menu buttons overlapped.** A screen keeps the buttons it is not drawing, and
the pause menu holds ones a mod has hidden. The game skips them; Kiza painted an
opaque panel over every button it found, so a hidden one came back as a solid
block lying across its neighbours — which is how "Mods" ended up underneath
"Report Bugs". Hidden buttons are skipped, one lying across a smaller one is
left alone, and a label too long for its button is trimmed instead of running
over what is beside it.

**The compatibility warning was a number.** "2 compatibility problems" and not a
word about which mods or why, when the launcher knew both: it will tell you
"Forge mod detected in a Fabric instance" against the file it found.

**CurseForge blamed the wrong thing.** A refusal was reported as "the author has
disabled third-party downloads" whatever had been asked — including over a list
of search results, where no author has any say. A refused search is the API key,
and it now says so, with where to fix it. The diagnostics page called CurseForge
reachable whenever the server answered, and a refusal is an answer; it asks
using the key the launcher actually uses, and tells you what came back.

**Mods added from a file claimed version 1.0.0.** A number no author wrote,
sitting beside real ones and compared against by the update check. The jar is
read for the version its author gave it.

**A Kiza mod that fails to load no longer takes the game with it.** Across ten
years of Minecraft versions a mod fails by not linking rather than by throwing,
and the runtime was only catching the second kind.

**A client runtime report outlived the launch that wrote it.** An instance last
played three weeks ago answered as though it were running now. Reports are
cleared when a launch begins, and the launcher says "at the last launch" when
that is what it means.

**The client panel claimed capabilities that had never started.** With no report
at all it drew every feature the version could have, in the same style as ones
that were working. The two are separated and labelled, and an instance that has
never been launched says so.

## Changed

**Instance settings say why a module failed.** The reason had always crossed
from the game to the launcher and was thrown away, leaving a red badge and no
explanation.

**Mod loader switches live in `client.properties`** beside each instance, and
settings a newer Kiza wrote are no longer erased by running an older one.
