Kiza Launcher 0.0.320

An imported CurseForge pack now puts its mods in the mod list, and a mod whose
author does not allow launcher downloads can be taken from Modrinth in one
click.

## Fixed

**An imported pack downloaded every mod and showed "0 installed".** The jars
were on disk and the game would have loaded all of them, but nothing had told
the launcher they were there. Shader packs and resource packs are listed from
the folder they sit in, so those looked right — the mod list, the update check,
the on/off switch and Share/Export all read the launcher's own record, and a jar
written straight into `mods/` was in none of it.

Mods are registered properly now, with what CurseForge knows about each one:
name, author, description, icon, page, size and the versions it is for. Where
each came from is recorded too, so the update check can offer a newer build —
without that they would sit in the list and never be offered one.

If you imported a pack with 0.0.319, the mods are still there and the game
loads them; re-importing the pack on this version will list them properly.

## New

**A blocked mod can be taken from Modrinth.** Some CurseForge authors switch off
third-party downloads. Where the same mod is published on Modrinth, the window
that lists what could not be fetched now offers to get it from there in one
click, beside the link to the project page.

This is not a way around anybody's decision: the switch an author flips is on
CurseForge and applies to CurseForge, and a mod published on Modrinth is
published there under Modrinth's own terms. An author who wants neither is on
neither, and then there is nothing to offer but the page.

It is offered rather than done automatically, because the Modrinth release is
whichever one fits your instance and not the exact build the pack pinned.
