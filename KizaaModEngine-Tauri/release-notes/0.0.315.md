Kiza Launcher 0.0.315

Four things found by using 0.0.314 for an hour, one of which took the whole
interface down.

## Fixed

**The launcher crashed on the first update check that worked.** The interface
has always declared that a mod carries the list of files it owns, and the
backend has never sent that list. Two places call a method on it — the update
list and the crash doctor — and neither could run while mods carried no
provenance, because nothing was ever found to update or to blame. Recording
provenance made the update check work, the first candidate reached that line,
and the interface died with "Cannot read properties of undefined". The field is
sent now, both places are defended against its absence, and a test compares what
the interface reads against what the backend actually sends.

**Exporting failed on "Duplicate filename".** A mod can appear twice in the
catalogue — installed directly, then registered again as somebody's dependency —
and both records name the same jar. The export added that file to the archive
twice, which a zip refuses outright, so the whole export failed. One jar, one
entry now.

**The same mod could be installed twice, from two catalogues.** Kiza identifies
a project as `provider:id`, so Modrinth's Fabric API and CurseForge's Fabric API
are strangers to each other: a pack whose mods come from both installs Fabric
API twice, and two copies of one mod in `mods/` is a game that will not start.
There is no shared identifier between the two platforms, so the name is what
decides, compared with the punctuation and the case taken out.

**An imported instance lost every mod's identity.** The archive carried each
mod's release but not what the catalogue knew about it, so an imported instance
listed the right names with no icons and "Imported File" under every one — the
launcher had forgotten a CurseForge mod came from CurseForge, because only
provenance travelled and a bundled mod has none. The description, the author,
the icon, the page and the catalogue it came from travel now.

## Changed

**Importing starts the game download.** Version files are shared between
instances, so importing a pack for a version you already play needs nothing.
On a machine meeting that version for the first time, the instance used to
arrive complete and unplayable until somebody noticed the Install button.
