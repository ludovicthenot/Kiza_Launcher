Kiza Launcher 0.0.333

The Kiza client now runs on a plain Minecraft, an instance that closed can no
longer say it is still playing, and when a game dies the launcher keeps what it
said as it went.

## New

**The client on Vanilla.** Until now a Vanilla instance got the launcher and
nothing else: the in-game menu, the frosted buttons, the background were for
Fabric and Forge only, because a mod needs a loader to start it and Vanilla has
none. It has one now — the launcher attaches the client to the game itself.

Minecraft ships with its names removed, which is why this was never simply a
matter of shipping the same mod: `Screen` is called `fod`, `GuiGraphics` is
`fhz`, and both change every release. Mojang publish the key to that for every
version since 1.14.4, and the launcher fetches it, so the client can ask what
the game calls things and get an answer.

Nothing about it can stop a game from starting. No key for that version, a
screen it does not recognise, anything at all going wrong — the client stands
aside and Minecraft opens exactly as it did before. A plain menu is a lost
decoration; a game that will not open is a lost evening.

## Fixed

**An instance that stopped being played said it still was.** Closing Minecraft
left the launcher insisting the game was running, with Play stuck reading "In
game" and a blank Kiza Manager window that could not be moved, minimised or
closed. Opening that window came before the launcher started watching the
process, so when the window did not finish opening, nothing was watching, and
the launcher never heard the game end. The watch now starts the moment the game
does, before anything draws.

**Stop can now stop an instance that already stopped.** Asked to stop a game
whose process was already gone, it reported an error and changed nothing —
which is exactly the case where it is the button somebody needs, since the
launcher's own record is the thing that is wrong.

**A crash keeps what the game said as it died.** The game's own output was
written to the file Minecraft's logger owns, and that logger renames it aside
on startup — taking the launcher's copy with it. So a game that died before
Minecraft's logger existed said why into a file nobody read, and the crash
panel came back saying it did not know either. The game now writes somewhere
nothing else touches, and the panel reads it.

**The crash panel recognises a modpack that arrived incomplete.** Forge says a
mod is missing once per mod that noticed, which in a pack built on shared
libraries is nearly all of them, so what somebody reads is hundreds of true
lines and no cause.

**A CurseForge pack says what it could not bring.** Some authors do not let
launchers download their mods. Those were counted and the list thrown away, so
the instance installed, read as healthy, and could not start. It now names
them, with the Modrinth copy where the same author publishes one.

**Old Forge tells the client what you are doing again.** On 1.7 through 1.12
the client reported that it could not tell — and said so on your Discord
profile, as "Minecraft state unavailable", which reads to your friends as a
broken game. It could not tell because it only knew the names Forge has used
since 1.13. It knows both now, and where it still cannot tell, it says you are
playing rather than announcing its own shortcoming.
