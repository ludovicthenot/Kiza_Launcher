Kiza Launcher 0.0.308

Three settings pages that were mostly headings now do the work they promised,
and two switches that had never governed anything finally do.

## New

**Notification channels.** Windows notices and messages inside Kiza are now
separate switches, each with its own off. Messages can be given a corner of the
window, and a short chime if you want one.

**Do not disturb.** Nothing interrupts while the game is running, and you can
set a quiet period — 22:00 to 08:00 by default, running over midnight the way
you would expect. A crash still gets through, unless you say otherwise.

**More to be told about.** The game starting, and a world backup finishing.

**A diagnostic report you can send.** One button writes a file with the version,
the system, what Kiza occupies, which services answered and how fast, and the
end of the last log. It carries no account name, no e-mail and no token, and
Explorer opens on it ready to attach.

**Logs no longer accumulate for ever.** Kiza keeps two weeks of them by default
— seven, thirty, ninety or all of them, as you prefer — and removes the rest at
startup. The page says how many files there are and how much they take.

**Two repairs that cannot lose anything.** Rebuild the instance list, for a
folder renamed by hand or an entry left behind by a delete that failed halfway.
Clear the metadata cache, which is fetched again the moment it is needed.

**Latency on the Connections page.** Modrinth, CurseForge, Microsoft sign-in and
the Mojang services, checked together and timed, with the figure next to each.
Every reading was measured; nothing shows green until it has answered.

## Fixed

**Two notification switches governed nothing.** "An update is ready to install"
and "The download queue has emptied" were written to the settings file and read
by no code at all — the moments they described were never watched for, so
turning either off changed nothing. Both are now real, and every notification in
the launcher goes through one place that reads them.

**The release build could not publish itself.** The workflow installed Node 20,
and the tool that uploads to the update service refuses to run below 22. The
launcher compiled, signed correctly, and then fell over on the last step. The
version check now catches that in a second rather than a quarter of an hour.

## Notes

Kiza asks its own update service first and falls back to GitHub. Both are
signed, and neither can make the launcher install a file it cannot verify.

The installer is not signed with a code-signing certificate, so Windows
SmartScreen will warn on first download.
