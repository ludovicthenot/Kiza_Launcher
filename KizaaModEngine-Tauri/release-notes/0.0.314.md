Kiza Launcher 0.0.314

Exporting an instance now exports the instance: you choose what travels, worlds
included, and what arrives somewhere else is an instance rather than a folder
that resembles one.

## Fixed

**An export left the worlds behind, and never said so.** What "export" wrote was
a manifest declaring no mods at all, plus `mods/` and `config/`. A real archive
here held sixty-eight entries for an instance whose nine-megabyte world it did
not mention; resource packs, shaderpacks and `options.txt` were not in it
either. There was nothing to choose — you got that, or nothing.

**An imported instance had an empty Mods tab.** Kiza keeps its mod catalogue in
a file the export left out and the import never rebuilt, so the jars arrived on
disk and the launcher did not know them: nothing to switch off, nothing to
remove, nothing to update. The import writes the catalogue now.

**Mods could never be offered an update.** The Update Centre reads one index and
one index only — where each file came from — and the code that installs a mod
never wrote to it. Only shaderpacks and resource packs were ever recorded. On a
real instance here that was twenty-five mods and three entries, none of them a
mod. The loop closed on itself: no record, no update offered, no update applied,
and applying one was what used to write the record.

Mods installed from now on are recorded. Mods installed before are worked out
from the files themselves — Modrinth and CurseForge will both answer "which
release is this exact file" — so an instance built over months becomes
updatable without reinstalling anything. A file neither platform recognises
stays unknown rather than being attributed to something plausible.

## New

**An export window.** Mods, mod configuration, resource packs, shaderpacks, game
options, and every world listed on its own with its size, its version and
whether it is hardcore. Nothing starts ticked: an archive is a thing people
share, and a world is the one item in there that is private.

**Mods travel as references.** A mod from Modrinth or CurseForge is a line in
the manifest rather than a few megabytes of jar, and the import fetches that
exact release — so the archive is a few hundred kilobytes instead of sixty
megabytes, and what arrives is the version that left. A mod added from a local
file has no release to name, so it is carried in full; so is any jar dropped
into `mods/` by hand, because the game loads the folder and not the catalogue.

**What was switched off comes back switched off.** The enabled state and the
load order travel with the instance. Restoring a disabled mod as enabled would
quietly change what the game loads.
