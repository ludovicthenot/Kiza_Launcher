Kiza Launcher 0.0.312

An update now takes effect when it is installed, rather than the next time you
happen to restart the launcher.

## Fixed

**An update no longer waits for a restart to take effect.** Windows will not let
a running program be overwritten. The installer knew this, waited ten seconds
for the launcher to let go, and then carried on regardless of the answer —
renaming the old build aside and writing the new one beside it. The install
reported success, the launcher carried on running the old version, and the
update only appeared the next time Kiza happened to be closed and reopened.

The installer now asks the launcher to close before it replaces anything, and
waits for it to actually go. It asks rather than kills: a launcher may be
holding a download, a running game or an installation of its own, and a
terminated process leaves those half done. The request travels on the same
channel that already carries `kiza://` links, so nothing new is left listening.

If the launcher will not let go, the install stops and says so instead of
finishing with a version that is not the one you will be running.

## Note on this one update

The launcher that answers this request is the one in this release. Updating
*to* 0.0.312 is therefore the last time Kiza has to be closed by hand: if the
installer finds an older launcher running, it will ask you to close it first.
Every update after this one closes it for you.
