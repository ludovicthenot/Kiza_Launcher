Kiza Launcher 0.0.309

The remaining settings pages now do the work they promised, and a size printed
in one corner of the launcher finally matches the same size printed in another.

## New

**About tells you what you are running on.** System, processor, cores, memory,
free space and engine, measured on the machine rather than guessed from the
browser, with one button that copies the lot as a pasteable block. The
installation identifier shown there is random, tied to no account, and exists
only so two diagnostic reports sent a week apart can be recognised as the same
install.

**Storage shows the drive, not just Kiza.** The bar marks out Kiza's share of
the real disk with what is actually free. Cached files are pruned by age when
Kiza starts, and a download can be deleted once it is installed into an
instance — neither can touch a world, an instance or a backup.

**One way of writing a size.** There were four separate size formatters in the
launcher and they did not agree, so the World Vault and the Storage page could
print different figures for the same folder. There is one now, and Language and
region chooses its units: what Explorer shows, binary (KiB, MiB), or decimal.

**An accent colour.** Any of seven presets or a colour of your own, overriding
whichever theme is selected. The text on top is chosen by luminance, so a
yellow accent gets dark text and a blue one gets light. The card underneath
previews it live.

**The Java runtimes are a list you can act on.** Which Minecraft versions each
one covers, whether it is here, what it occupies, and install, repair or
remove. A runtime folder missing its java binary now reports as broken instead
of installed — that is what a cancelled download leaves behind.

**Downloads can be told how hard to try**, from one attempt to six, and can
hold the queue while the game runs. Transfers already in flight finish rather
than being torn down; only queued files wait. The page shows what is arriving
right now.

**New instances have a default performance profile** that can be changed after
the first-run wizard rather than only during it.

## Fixed

**Two notification switches governed nothing.** "An update is ready to install"
and "The download queue has emptied" were written to the settings file and read
by no code at all. Both are real now, and every notification goes through one
place that reads them.

**Notification channels, quiet hours and a do-not-disturb** for while the game
is running, with a crash still allowed through unless you say otherwise.

**The Advanced page** writes a diagnostic report you can attach to a message,
prunes logs on a retention period honoured at startup, and offers two repairs
that cannot lose anything.

**Connections measures what it reports.** Latency beside each service and a
reachability grid for the four a launch depends on. Nothing shows green until
it has answered.

**The release build could not publish itself.** The workflow installed Node 20
and the upload tool refuses to run below 22, so the launcher compiled, signed
correctly, and fell over on the last step. The pre-flight check now catches
that in a second rather than a quarter of an hour.

## Notes

Some things in the designs are deliberately absent, because the machinery
behind them does not exist yet and a control that governs nothing is worse than
one that is missing: proxy and DNS settings, hardware acceleration, experimental
feature flags, moving the Kiza folder, and a first-day-of-the-week setting for a
launcher that draws no calendar.

Kiza asks its own update service first and falls back to GitHub. Both are
signed, and neither can make the launcher install a file it cannot verify.

The installer is not signed with a code-signing certificate, so Windows
SmartScreen will warn on first download.
